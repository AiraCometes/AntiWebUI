## Purpose and scope

What the constitution governs: the framework repository, not design kits or applications.

## Principles

### Principle name

- Statement: one sentence, written as an obligation (MUST or SHOULD).
- Rationale: why the project pays this cost.
- Guarantee boundary: exactly what is and is not covered.
- Verification: the fitness function, test, benchmark, or review step that checks it. Write `none yet` and link the plan when no check exists.
- Exceptions: how an exception is approved and recorded.

## Priority between principles

The order used when two principles conflict, with one example.

## Amendment process

How a principle is added, changed, or removed (an ADR plus maintainer approval).

## Non-goals

What the project deliberately does not do.
